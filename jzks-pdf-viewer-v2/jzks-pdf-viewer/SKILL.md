# jzks-pdf-viewer

把论文精读写成五个相互连接的部分，并把重要判断接回原文。宿主AI负责阅读和写作，脚本负责定位、批注和生成阅读器；网页本身不调用模型。

## 使用

用户可以说：“请调用jzks-pdf-viewer，完成这篇论文的精读。” 已有明确PDF时直接开始。阅读目的未指定时，按下列五步均衡阅读。

1. 作者想解决什么问题：研究动机、已有缺口与贡献。
2. 用了什么方法：对象、数据、设计、模型、对照及重要假设。
3. 得到了什么结果：关键图表、指标与比较关系。
4. 结果能否支持结论：对照证据与主张，指出缺失或冲突。
5. 有哪些局限与启发：区分作者的未来工作和AI的分析，提出有依据的启发。

每步的可展示提示词见 [references/five-steps.md](references/five-steps.md)。不要把五步写成五份互不相关的摘要。

每次读取 [references/deep-reading.md](references/deep-reading.md)，落实全局地图、可检验假设、知识缺口、研究类型对应的方法检查、证据与作者主张对照、可验证的替代解释。先形成`evidence-conclusions.md`再对照讨论；已经见过作者结论时如实按“证据复核”执行。解释贡献与原理，不能只列问题。

## 阅读与证据

- 确认PDF标题、页数和全文范围。使用环境提供的PDF阅读工具（有MinerU时优先），读取全文及关键图表。Markdown可作中间材料，但保持物理页码。
- 文字型PDF是首版支持范围。扫描页需要带坐标OCR；若缺少OCR或原页，不生成虚构的逐句定位。可输出已有精读内容并明确待补页面。
- 将作者明确报告的内容标为`author`，AI分析标为`analysis`，未找到的信息写“本文未报告”并说明已查范围。没有方法细节不等于证明作者没有执行。
- 重要数字对照原表图，不依据参考工具的精读卡替代原文。作者表述与表格冲突时并列记录，不能擅自选择一方。
- 每项批注填写实际原文短引句、物理页码、解释和所属步骤。多个证据共同支持一段时引用多个批注。原文不支持的强判断降级或删除。

## 生成

按 [references/card-schema.md](references/card-schema.md) 创建`reading.json`，包含完整五步正文和证据批注。正文不是关键词清单；每步说明事实、为什么重要及必要边界。

运行本Skill中的脚本（把`SKILL_DIR`替换为本文件所在目录）：

```text
python "SKILL_DIR/scripts/build_viewer.py" --pdf "论文.pdf" --card "reading.json" --out "精读结果"
```

需要Python与PyMuPDF：缺失时在项目环境安装`pymupdf`。脚本不调用外部模型、不上传PDF。不要在首次调用时触发无关Skill或额外服务。

脚本生成：
- `index.html`：自包含阅读器；正文复制、原文跳转、中文批注、专注模式、批注筛选与高亮开关；自动保存阅读位置、缩放及筛选。手工勾画可编辑，用户纠正附在原AI批注旁。
- `paper-card.md`、`reading.json`：精读正文及结构化记录。
- `evidence-index.json`、`annotation-map.json`：证据与坐标。
- `annotated-paper.pdf`：保留原页并增加高亮和中文边栏。
- `build-report.json`：实际定位成功、歧义和未定位的条目。

检查`build-report.json`。未定位条目只能跳页，不能伪造高亮。必要时修正引句后重建。网页下载批注PDF时，将AI批注、手工勾画和个人纠正合并；脚本生成的初始PDF只有生成时的AI批注。笔记也可导出JSON备份或跨浏览器导入。PDF边栏按原文位置排序，尽量靠近证据并避让，空间不足续页。

交付前实际打开网页，检查至少一个证据链接、页码切换、正文复制和手工勾画保存。确认原文与解读相互对应，然后给网页与下载文件。
